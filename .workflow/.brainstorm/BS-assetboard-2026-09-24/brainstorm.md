## 第 1 轮：发散与研究

### 创意视角

- 项目资产架：每个项目占一组，资源按功能排列；看到用途，再看到服务商。
- 全局速查：按域名、项目昵称、账号别名、供应商搜同一批资产。
- 安静的时间条：只突出接下来需要处理的事，日历作为次级视图。
- 找回收件箱：导入后先展示候选归属；可批量确认，不强迫逐项整理才能使用。
- 项目记忆：一句“为什么留着它”，防止半年后再次迷失。

### 务实视角

- 首页即使未连接账户，也应能通过少量链接和手动记录建立价值。
- OAuth 减少最终用户操作，但不消除应用注册、权限审核和连接器维护。
- 数据来源越多，去重、过期与冲突问题越多；不能用接口数量代表产品完成度。
- 不把全邮箱扫描作为第一屏价值的先决条件。
- 第一批接哪些平台，应根据实际资产分布选择；GitHub、Cloudflare、Vercel 只是候选。

### 系统视角

- 项目、资产、账号、费用、事件、关系、来源分开表达，前台可以很简单。
- 同一资产可服务多个项目；未归属、共享、停用均为正常状态。
- 同步连接状态、资产使用状态、外部运行状态必须独立。
- 每个重要事实应有来源和时间；推断不能覆盖用户确认。
- 账单和资源之间允许一对多、多对一；共享费用不可重复相加。

### 决策记录

> 决策：推荐“项目分组的资产架 + 近期事件 + 全局搜索”为默认首页。
> 原因：同时回应“在哪里、做什么、下一步是什么”，可自然容纳未归属和共享资产。
> 对比：服务商网格易认但弱化项目用途；全局关系图表现力强但搜索和扫描成本高；纯到期表无法解释基础设施。
> 影响：关系图放进项目详情，费用视图与日期视图复用同一批事实。

### 已挑战的假设

- “很多独立开发者都需要” → 用户自身痛点明确，群体需求和授权意愿仍待验证。
- “Cloudflare 里有域名就有续费日” → DNS zone 与注册记录不同，必须区分来源。
- “开源就能解决信任” → 仍需限制权限、保护凭证并解释数据去向。
- “自动发现比 UI 更重要” → 自动发现和日常查找均重要；本次用户明确要求优雅的一览体验，不能被连接器工程淹没。
- “金额相加就是月支出” → 固定承诺、实际用量、估算和共享费用需要区分。

## 第 2 轮：根据反馈调整

用户选择视觉和交互优先。保留平台能力作为边界，将设计展开为 A 项目资产架、B 资产目录、C 局部关系地图；优先比较 A/B，暂不限定发布方式。根目录文档补齐首屏骨架、添加/搜索/详情/日期的行为、边界样本和建议验收任务。

与前一轮相比，输出重心从产品接入顺序转向信息组织和日常操作。后续方向作为可选问题提出，本轮不进入实现。

## 第 3 轮：UI / UX 为首要研究

用户进一步强调：“既然这个是展示和管理功能，那么就要研究 UI 和 UX，这是重中之重”。补充 NN/g、Carbon、Linear 和 W3C 的一手资料，形成根目录 ASSETBOARD-UI-UX.md。

决策修正：项目资产架降为待验证候选，与资产目录和常用入口视角比较。区分日常阅读与选中后的管理状态，明确完整任务链、失败恢复、视觉变量与用户测试方法。现有文档新增优先级说明，不将文献研究冒充用户验证。

## 第 4 轮：小组件式分区大板

用户明确希望“一张大板划分区域”，类似 iOS 小组件编辑，查看与编辑 UI 差异小。主界面收敛为可编排大板：原本的项目、目录、入口转化为组件类型。补充 ASSETBOARD-BOARD-DESIGN.md，规定查看/编辑视觉连续、布局与资料编辑分离、移动和删除的语义、尺寸吸附与跨设备稳定性。用户确定总体方向，操作细节仍为待验证建议。

## 第 5 轮：类别区块与资产卡片

用户明确“区域大小应该自适应 + 最小限制”，支持放大缩小，并按类别加入区块、区块内部放资产卡片。撤回固定小中大尺寸建议与混合组件作为默认组织的方案，更新为大板、类别区块、资产卡片三层结构。默认高度随内容增长；手动调整、溢出展示、后台更新稳定性等细节记录为设计建议，尚未测试。同步更新简报、UI / UX 入口与综合结论。

## 第 6 轮：展示和展开的细节

用户要求细化哪些折叠、哪些展示以及交互展开形式。新增 ASSETBOARD-DISCLOSURE.md：区块收起后保留摘要，卡片保持核心信息，查看全部进入类别完整视图，资产详情使用桌面侧边面板/手机独立页。明确自动高度、手动高度与折叠状态互不覆盖，搜索不破坏布局，重要事件不因折叠失去提示。以上是待验证设计建议，未进入原型实现。

## 第 7 轮：图形化优先

用户强调“图形化才是最重要的”。据此修正此前偏文字字段的表述：卡片以资产形象和图形状态为主，短文字辅助精确识别；区块用空间和类别图形分组，折叠后保留缩略识别线索，展开保持视觉连续。记录到项目设计文档，作为后续原型的最高视觉优先级。

## 第 8 轮：原型实现

用户明确要求出原型，并补充极简、优雅、丝滑，随后强调“不要别的东西，只要这块板子”。已实现 index.html/styles.css/app.js，删去初版侧栏、标题介绍和页脚，只保留资产板与搜索/添加/布局工具。演示数据、SVG 资产图形与本地持久化。已完成浏览器核心交互检查及 390px 无横向溢出检查，细节见 PROTOTYPE.md。原型实现是本轮新增授权，不延伸到平台接入或发布。

## 第 9 轮：本地 Mac App

用户希望 App 形式、本地存储。实现原生 Cocoa 窗口 + 内置 WebKit，打包为 dist/Assetboard.app；静态资源全部内置，不依赖网页服务器。数据写入 Application Support/Assetboard/board.json，原子写入并保留上一版备份。实测 UI 折叠、文件写入、退出重启后恢复；本机 App 已打开。尚未公证或分发，不包含账户接入。

所有优先级均为本轮建议，尚无用户逐项确认、真实资产导入或可用性测试。研究与资料整理已完成；下一轮可选布局深化、数据样本或开发范围，不自动进入实现。
